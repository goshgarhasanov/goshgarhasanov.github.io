About

I usually run a project on my own: I build the database, the API, and the web, mobile or desktop app that calls it. That has one real advantage. When I write the API I already know how it will be used later, so nobody has to come back at the end and ask me to return that response some other way.

Most of my time goes into the database. If the schema is wrong from the start, no amount of tidy API code on top of it saves you. I don't hand a project off at deploy either: I read the logs and I find and rewrite the slow queries. Almost everything I write runs on Docker and Linux.

What I do

Frontend

I build interfaces with React and Next.js. I care about the page opening quickly on a phone, the HTML being written properly, and not shipping JavaScript the browser never needed.

Backend

I write APIs in Python (FastAPI, Flask) or Node.js. Login and sessions, validating what comes in, pushing long jobs onto a Celery queue, keeping frequently requested answers in Redis. These come up in almost every project.

Databases

I work with PostgreSQL and MongoDB. I shape the schema around the project from the start, then go looking for the slow queries: some are only missing an index, others are easier to rewrite from scratch.

Mobile · React Native

With React Native I write one codebase for both iOS and Android. The business logic stays shared, and where React Native does not reach I write a native module.

Desktop Apps

I build desktop apps with Electron that run on Windows, macOS and Linux. For lighter tools I use PyQt5 and Tkinter, which sit closer to the look of the system itself.

DevOps · Linux

I package a project into Docker and put it on a Linux server or on AWS; when it is needed I reach for Kubernetes, Lambda, ECS and SQS. Nginx, process managers and deploying over Git are part of the daily routine.
